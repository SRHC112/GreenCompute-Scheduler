## 一、项目背景与目标

宁夏中卫—银川算力枢纽汇聚了大量 A100/H800/A800 GPU 资源，电价按峰谷分时浮动、绿电出力日内波动、碳排放因子高于全国平均水平。传统调度多为固定优先级或先到先服务（FCFS）规则脚本，存在三类问题：

1. **成本与绿电不可协调**：未把峰谷电价与绿电窗口纳入同一目标函数，成本低的时段未必绿电多，绿电好的时段未必电价低（正午光伏最强恰逢峰电价）。
2. **缺陷不可归因**：验证失败后整批重排，无法定位是「估错了」还是「排错了」，返工成本不可控。
3. **不可复现**：依赖第三方模型或云端接口，评审现场无法离线复现，指标数字不可追溯。

本项目提出一个**七角色、八状态、可定向返工、全确定性可复现**的多智能体算力调度编排系统，将调度从规则脚本升级为 Agent 编排创新应用。

### 1.1 核心目标

| 目标 | 量化指标 | 验证方式 |
|---|---|---|
| 多 Agent 协作 | 7 个角色（A1~A7）完成 PARSE→PLAN→SCHEDULE→EXECUTE→VERIFY→REFLECT→REWORK→REPORT 闭环 | 代码角色卡 + 运行日志 |
| 自我循环机制 | VERIFY→REFLECT→REWORK 定向返工，缺陷只退给责任节点 | 返工日志与缺陷归因 |
| 智能化而非硬编码 | 所有先验参数（电价、绿电、资源池、权重）外置为版本化知识包；目标函数由知识包权重计算得出 | 知识包 YAML + trace_fit.py 校验 |
| 可视化界面 | 单文件零依赖 console.html 看板（DAG / 轨迹 / 指标），离线双击即打开 | runs/latest.html |
| 指标可复现 | 同种子必得同一批作业与同一指标 | unittest + 确定性模拟器 |
| 合规达标 | SLA 达成率 100%、预算达标率 100%、绿电窗口作业占比提升 | evaluation/summary.md |

### 1.2 适用赛道与评分点

- 赛道：2026 第五届「未来杯」创新大赛 · 赛道一「Agent 编排创新应用」
- 技术栈：Python，国内 LLM API 仅为可选接入，离线运行不消耗模型额度
- 团队规模：≤ 5 人
- 开源框架：允许使用，但须有原创改进（本项目原创：七角色八状态机、五层验证器、六维 rubric、定向返工、知识包外置、帕累托前沿分析）

## 二、使用者与使用场景

| 角色 | 职责 | 主要操作 |
|---|---|---|
| 算力调度员 | 提交作业批次，查看调度结果 | 通过操作台发起作业，设置 SLA 与预算 |
| 运维工程师 | 监控集群状态，处理返工升级 | 查看缺陷归因，决定是否人工介入 |
| 评审专家 | 验证系统功能与可复现性 | 运行 `python -m unittest discover -s tests`，查看 `evaluation/` 产物 |

典型场景：一批 40–80 个 GPU 作业（训练/推理/批处理）提交后，系统自动完成调度、执行、验证、反思、返工，生成带可视化看板的完整报告。

## 三、功能需求

### 3.1 作业解析与规划（A1 Profiler / A2 Planner）

**FR-01** 支持批量导入作业清单，每条作业携带：ID、类型（train/infer/batch）、GPU 卡数需求、预计时长、截止时间、预算上限、SLA 余量。
**FR-02** A2 基于知识包 `job_profiles` 给出逐作业时长估计、置信度、估计方法与证据；不完整的作业挂起等待人工补充。
**FR-03** 估计错误（实际/估计 > 1.2）与排错（实际 ≤ 1.2 但未达标）在 REFLECT 阶段区分对待，分别退给 A2 重估或 A3 重排。

### 3.2 调度与执行（A3 Scheduler / A4 Executor）

**FR-04** 在满足硬约束（截止时间、预算超支 ≤ 15%、最小绿电占比 40%）前提下，对多个软目标（等待、成本、绿电、碳排、拥塞）加权最小化。
**FR-05** 候选起点不仅包含「最早可排时刻」，还主动对齐谷段电价起点与峰段终点，实现成本与绿电窗口的真实权衡。
**FR-06** 每条调度决策附带对照依据 `_rationale`：选定什么、因为什么排除了更便宜或更绿的候选。
**FR-07** 执行侧只负责「发现异常」，不做判定；判定权在 A5 Verifier，避免自证。
**FR-08** 支持故障注入（GPU 超时、卡故障），验证系统在异常下的降级行为。

### 3.3 验证与自省（A5 Verifier / A6 Reflector）

**FR-09** 五层验证器：L1 结构 / L2 数值复算 / L3 约束 / L4 可达性 / L5 语义 Judge。能用规则判的不交给模型。
**FR-10** 输出不是「通过 / 不通过」，而是缺陷清单，每条带 `code / layer / owner / node / detail / evidence / action`。
**FR-11** 六维 rubric 评分：硬约束 30 / 数值与口径一致性 20 / 证据强度 20 / 任务覆盖度 15 / 结构合规 10 / 成本效率 5，通过阈值 80。
**FR-12** 缺陷仅退给责任节点子树重跑，保留其余作业原排程，避免整批重排引入新的 SLA 违约。

### 3.4 报告与可视化（A7 Reporter）

**FR-13** 生成单文件零依赖 `console.html` 看板（DAG 拓扑 / 运行轨迹 / 指标表），双击即可离线打开，不依赖任何 CDN。
**FR-14** 生成 Markdown 报告与结构化 `metrics.json`，所有指标可追溯到 `evaluation/results.csv` 逐行原始数据。
**FR-15** 输出对照实验结果（G-A ~ G-E2 六组配置 × 3 种子）、帕累托前沿、置信区间。

### 3.5 非功能需求

| 需求 | 指标 |
|---|---|
| 可复现性 | 同种子 + 同参数必得完全相同指标 |
| 零依赖运行 | 除 PyYAML 外无第三方运行时依赖；看板不引用任何 CDN |
| 离线运行 | 不配置 LLM 环境变量也能跑通全流程，模型层退化为离线确定性模板 |
| 可扩展性 | 知识包版本化，替换电网/园区实时接口时仅需升级 version，无需改代码 |
| 团队规模 | ≤ 5 人 |

## 四、约束与边界

1. 模拟器只负责「按计划执行并给出真实结果」，不含任何调度逻辑——调度决策全部来自 Agent。
2. 所有指标数字由确定性模块计算，模型只产出归因叙述与语义层 Judge 意见，避免 LLM 幻觉污染指标。
3. 缺陷归因区分「估错了」与「排错了」，修复动作完全不同，不得混为一谈。
4. 返工预算：`max_rounds=2`、`max_tokens=600000`、`max_seconds=900`，超限升级人工并保留现场。
5. 面向用户的所有可见文本（回复、界面、提示、报错、生成文件中的可见文字）一律使用中文。

## 五、验收标准（与验收单对应）

- `python -m unittest discover -s tests -v` 全部通过（65 个测试）。
- `python evaluation\trace_fit.py` 四项硬断言全部通过（电价时段、峰谷比、排放因子、绿电曲线）。
- `python -m gcs.demo --jobs 60 --seed 20261111` 生成 `runs/latest.html` 且可在浏览器离线打开。
- `python evaluation\run_eval.py` 产出 `results.csv`（18 行）、`summary.md`、`eval_report.html`。
- SLA 达成率 100%、预算达标率 100%、rubric 终评 ≥ 80。
