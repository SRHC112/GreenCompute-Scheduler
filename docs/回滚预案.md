# 回滚预案

绿算调度 GreenCompute-Scheduler — 2026 第五届「未来杯」创新大赛 · 赛道一「Agent 编排创新应用」

**版本**：1.0（提交版）  
**知识包版本对齐**：nx-2026.12

---

## 一、目的

在知识包升级、代码变更或运行产出异常时，能够快速将系统恢复到已验证可用的状态，确保答辩现场与提交作品处于可运行、可复现状态。

---

## 二、回滚触发条件

出现以下任一情况时，应立即启动回滚：

| 触发条件 | 表现 |
|---|---|
| 单元测试不全绿 | `python -m unittest discover -s tests -v` 出现失败或错误 |
| 知识包对齐失败 | `python evaluation\trace_fit.py` `all_passed: false` |
| 对照实验产出缺失 | `evaluation/results.csv` 不足 18 行，或缺少 `summary.md` / `eval_report.html` |
| 看板不可打开 | `runs/latest.html` 缺失或浏览器离线打开异常 |
| 代码误删函数体 | 类似 `gcs/agents.py` 中 `Scheduler._best` / `Executor.run` 被误删为仅含文档字符串（历史已发生） |

---

## 三、回滚步骤

### 步骤 1：确认当前状态

```bash
# 查看工作目录状态
cd GreenCompute-Scheduler

# 查看最近提交
git log --oneline -5

# 查看工作区修改
git status --short
```

### 步骤 2：回滚知识包版本

若 `knowledge/ningxia_cluster.yaml` 最近被修改导致 `trace_fit.py` 不通过，回滚到上一已知可用版本：

```bash
git show HEAD~1:knowledge/ningxia_cluster.yaml > knowledge/ningxia_cluster.yaml
# 将 version 字段改回上一可用版本（如 nx-2026.11 或之前的已提交版本）
```

> 注意：回滚知识包后，必须重新运行 `python evaluation\trace_fit.py` 确认四项硬断言全部通过，再重新运行 `python evaluation\run_eval.py` 刷新评测数字。

### 步骤 3：回滚代码文件

若某个源码文件被误改（如函数体被误删），从最近一次可用提交恢复：

```bash
# 恢复单个文件到 HEAD
git checkout HEAD -- <文件路径>

# 或恢复到指定提交
git show <提交ID>:<文件路径> > <文件路径>
```

历史案例：`gcs/agents.py` 中 `Scheduler._best` 与 `Executor.run` 被误删，已通过 `git show HEAD:gcs/agents.py` 逐函数还原，并新增 CI 体结构校验步骤（参照前序 DEF-01/02，实际不依赖 `audit_bodies.py`）防止复发。

### 步骤 4：回滚评测产物

若 `evaluation/` 下的 `summary.md`、`results.csv`、`eval_report.html` 被意外覆盖，可从 Git 最近提交恢复：

```bash
git checkout HEAD -- evaluation/
```

> 提醒：`runs/` 目录已在 `.gitignore` 中忽略，运行产物不入库；若 `runs/latest.html` 缺失，重新运行 `python -m gcs.demo --jobs 60 --seed 20261111` 即可再生成。

### 步骤 5：回滚后验证

回滚完成后，必须依次执行以下验证，全部通过后才恢复使用：

1. `python -m unittest discover -s tests -v` → `Ran 74 tests ... OK`
2. `python evaluation\trace_fit.py` → `all_passed: true`
3. `python evaluation\run_eval.py` → 产出 `results.csv`（18 行）、`summary.md`、`eval_report.html`
4. `python -m gcs.demo --jobs 60 --seed 20261111` → 生成 `runs/latest.html` 且浏览器可离线打开

## 四、已知风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 知识包参数与公开口径不一致 | trace_fit.py 作为 CI 卡口，`all_passed: false` 时阻止提交 |
| 测试数字随知识包版本变化 | summary.md 标注知识包版本，提交前必须同步重跑并更新 |
| 函数体被误删不易察觉 | `audit_bodies.py` 定期执行，发现 `BODY-LOST` 即告警 |
| Windows GBK 终端导致中文输出乱码 | 程序强制 UTF-8 输出；终端执行 `chcp 65001`；trace_fit.py 避免非 ASCII 字符 |
