## 使用说明

所有用例可通过单条命令批量执行：

```bash
python -m unittest discover -s tests -v
```

预期输出：`Ran 65 tests ... OK`，耗时 < 1 秒。

知识包机器校验用例（TC-25）通过独立脚本执行：

```bash
python evaluation\trace_fit.py
```

预期：四项检查全部「通过」，`all_passed: true`。

## 用例详情

### TC-01 作业清单按种子生成（FR-01）

- **前置**：`PACK = KnowledgePack.load(knowledge/ningxia_cluster.yaml)`
- **输入**：`make_jobs(PACK, n=25, seed=7)` 执行两次
- **预期**：两次返回的 `[(j.id, j.duration_actual, j.budget) ...]` 列表完全相等
- **所在**：`tests/test_smoke.py::TestSimulator::test_jobs_are_deterministic`

### TC-02 作业字段完整（FR-01）

- **输入**：任意一条作业 `j`
- **预期**：`j.id`、`j.type`、`j.gpus`、`j.duration_actual`、`j.deadline_min`、`j.budget`、`j.sla_slack` 均非空且类型正确
- **所在**：`tests/test_smoke.py`（通过 make_jobs 断言间接覆盖）

### TC-03 A2 时长估计与置信度（FR-02）

- **输入**：`profiler_learn_safe` 对一组作业
- **预期**：输出包含估计时长、置信度、估计方法标注、证据；估计误差在合理区间
- **所在**：`tests/test_llm.py` 离线模式相关测试

### TC-04 估计误差与排错区分（FR-03）

- **输入**：实际/估计比值 > 1.2 的缺陷；实际/估计 ≤ 1.2 但未达标的缺陷
- **预期**：前者退给 A2（`n_rework_profile`），后者退给 A3（`n_rework_schedule`）
- **所在**：`tests/test_reflect.py`

### TC-05 多目标目标函数权重（FR-04）

- **输入**：`Orchestrator._weights(jobs)` 基于知识包 `job_profiles`
- **预期**：返回每个作业的 5 维权重字典 `{wait, cost, green, carbon, reliability}`
- **所在**：`tests/test_pareto.py`（通过 `_scale_one` 间接验证）

### TC-06 权重缩放和为 1（FR-04）

- **输入**：`Orchestrator._scale_one(w, "wait", 4.0)`
- **预期**：`sum(scaled.values())` 约等于 1.0，且 `scaled["wait"] > w["wait"]`
- **所在**：`tests/test_pareto.py::TestWeightScaling::test_scaled_weights_keep_sum_one`

### TC-07 候选起点对齐电价时段（FR-05）

- **输入**：`Scheduler._candidate_starts` full 模式
- **预期**：候选集中包含谷段电价起点与峰段终点对齐的起点
- **所在**：`tests/test_scheduler.py`；机器校验见 `evaluation/trace_fit.py` 电价时段对齐（24 小时 0 不匹配）

### TC-08 决策对照依据（FR-06）

- **输入**：`Scheduler._rationale(job, best, scored)`
- **预期**：返回非空字符串，含「因何排除、因何选定」对照说明
- **所在**：`tests/test_agents.py`；语义 Judge 见 `tests/test_llm.py::TestSemanticJudge`

### TC-09 Executor 只发现异常（FR-07）

- **输入**：`Executor.run(jobs, plan, cluster)`
- **预期**：`retries` 等于 `results` 中 `not sla_ok` 的作业数；不做任何判定
- **所在**：`tests/test_agents.py`

### TC-10 故障注入降级（FR-08）

- **输入**：模拟器注入 GPU 超时 / 卡故障
- **预期**：故障作业被标记，其余作业继续执行，系统不崩溃
- **所在**：`tests/test_simulator.py`

### TC-11 ~ TC-15 五层验证器（FR-09）

| 用例 | 验证层 | 输入 | 预期 |
|---|---|---|---|
| TC-11 | L1 结构 | 结构不合规的方案 | 被 L1 拦截，输出结构缺陷 |
| TC-12 | L2 数值 | 数值与口径不一致的方案 | 被 L2 复算后拦截 |
| TC-13 | L3 约束 | 违反截止时间 / 预算 / 绿电占比 | 被 L3 拦截，归因为约束类 |
| TC-14 | L4 可达性 | 不可达节点 | 被 L4 拦截 |
| TC-15 | L5 语义 | 缺失 `choice` 或 `exclusion` 的判定文本 | Judge 不通过 |
- **所在**：`tests/test_verifier.py`、`tests/test_llm.py`

### TC-16 缺陷清单字段齐全（FR-10）

- **输入**：`Defect` 实例
- **预期**：`code / layer / owner / node / detail / evidence / action` 字段均存在且非空
- **所在**：`tests/test_verifier.py::TestDefectStructure`

### TC-17 六维 rubric 打分（FR-11）

- **输入**：运行结果与验证报告
- **预期**：得分在 0~100，硬约束 30 / 数值一致性 20 / 证据强度 20 / 任务覆盖度 15 / 结构合规 10 / 成本效率 5；≥ 80 判为通过
- **所在**：`tests/test_reflect.py::TestRubric`

### TC-18 定向返工只重跑责任子树（FR-12）

- **输入**：缺陷带 `owner` 与 `node`
- **预期**：只重跑责任节点子树，其余作业原排程保留，不引入新的 SLA 违约
- **所在**：`tests/test_orchestrator.py::TestRework`

### TC-19 返工阈值敏感性（FR-12）

- **输入**：返工阈值 60/70/80/90/95
- **预期**：平均返工轮次与终评 rubric 分档稳定，满分不因门槛调低而出现
- **所在**：`tests/test_pareto.py`（参考 evaluation/summary.md 敏感性分析表）

### TC-20 console.html 看板（FR-13）

- **输入**：运行 `python -m gcs.demo --jobs 60 --seed 20261111`
- **预期**：`runs/latest.html` 存在，单文件零依赖，无 CDN 引用，浏览器离线可打开
- **所在**：`tests/test_report.py`；CI 操作台 HTTP 探测

### TC-21 报告可追溯（FR-14）

- **输入**：`report.md`、`metrics.json`、`evaluation/results.csv`
- **预期**：指标可追溯到 results.csv 逐行原始数据
- **所在**：`tests/test_report.py`；CI 校验 `results.csv` 18 行且每组 3 次

### TC-22 对照实验产出（FR-15）

- **输入**：`python evaluation\run_eval.py`
- **预期**：`results.csv` 18 行（6 组 × 3 种子）、`summary.md`、`summary.json`、`eval_report.html`、`pareto.json`
- **所在**：CI `evaluation` Job

### TC-23 帕累托前沿非支配点（FR-15）

- **输入**：`evaluation/run_eval.py` 中 `run_pareto()`
- **预期**：`pareto.json` 含非支配点集合、knee 点、"几乎免费" 点与数据驱动 verdict
- **所在**：`tests/test_pareto.py`；`evaluation/pareto.json`

### TC-24 95% 置信区间（FR-15）

- **输入**：`evaluation/summary.md`
- **预期**：含差值与 95% 置信区间表，判定口径为「区间不含 0 记为显著」
- **所在**：`evaluation/summary.md` 差异的 95% 置信区间节

### TC-25 知识包对齐硬断言（FR-05 / NFR-04）

- **输入**：`python evaluation\trace_fit.py`
- **预期**：分时电价时段 24 小时 0 不匹配；三个池峰谷比均为 1.6 / 0.6；`grid_carbon_factor == 0.6773`；绿电曲线皮尔逊相关系数 ≥ 0.85；`all_passed: true`
- **所在**：`evaluation/trace_fit.py`

### TC-26 同种子完全复现（NFR-01）

- **输入**：同 seed 下两次运行 `Orchestrator(...).run(jobs)`
- **预期**：`cost_per_gpu_hour` 与 `avg_wait_min` 完全相等
- **所在**：`tests/test_pareto.py::TestWaitWeightEffect::test_same_seed_is_reproducible`

### TC-27 除 PyYAML 外无第三方依赖（NFR-02）

- **输入**：`requirements.txt`
- **预期**：仅 `PyYAML>=6.0,<7.0` 一项
- **所在**：CI `test` Job 语法编译 + `import yaml` 校验

### TC-28 无 LLM 凭据进入 mock 模式（NFR-03）

- **输入**：不设置 `GCS_LLM_*` 环境变量
- **预期**：系统退化为离线确定性模板，指标数值不变，全流程可跑通
- **所在**：`tests/test_llm.py::TestOfflineMode::test_without_credentials_it_runs_in_mock_mode`

### TC-29 知识包版本化（NFR-04）

- **输入**：`knowledge/ningxia_cluster.yaml`
- **预期**：`version` 字段存在且为 `nx-2026.12`；`fingerprint()` 两次调用结果相等
- **所在**：`tests/test_smoke.py::TestKnowledge`

### TC-30 面向用户可见文本一律中文（NFR-05）

- **输入**：代码字符串、`app/server.py`、`gcs/report.py`、`docs/*`、`README.md`、生成文件
- **预期**：界面文字、提示信息、报错说明、生成文件中的可见文本一律使用中文
- **所在**：人工抽检
