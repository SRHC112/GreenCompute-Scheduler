## 六、附件：各赛题详细介绍 —— 赛题 1：Agent 编排创新应用

本赛项以「大模型 Agent 工具编排调度平台」为主题，要求参赛选手设计并实现一套面向多智能体（Multi-Agent）协作的编排、调度、执行与验证平台。竞赛目标对标 Lobehub、DeepSeek Harness 等主流 Agent Harness 框架，重点考察选手在知识库定义与集成、Agent 团队定义、工作流编排、动态调度、自我循环（Self-Loop）、结果验证与反馈优化等全链路工程化能力的掌握程度。参赛选手需围绕一个真实或模拟的复杂任务场景，构建可运行的平台系统，形成完整的技术方案与演示成果。

### 一、赛题背景

当前，大模型应用正从「单轮对话」向「具备复杂任务处理能力的多智能体协作」快速演进。科研与产业界已涌现出一批 Agent 编排框架（Claude、Lobehub、DeepSeek Harness），但在实际落地中仍面临三大核心挑战：

- **首先是「编排能力薄弱」**：现有方案多为脚本化或硬编码的 Agent 流水线，缺乏可视化的工作流设计器、动态条件分支、循环控制与异常回退机制，难以应对复杂任务中的不确定性；
- **其次是「调度策略单一」**：多数开源框架采用简单的串行或广播式通信，缺乏基于任务优先级、资源负载、Agent 能力画像的智能调度，更不具备自我循环（Self-Loop）与迭代优化能力；
- **最后是「验证与可信机制缺失」**：Agent 输出的中间结果与最终结果缺乏自动化的验证、交叉核对与人工介入节点，导致多 Agent 协作的「幻觉」与错误传播难以收敛，系统可解释性与可复现性不足。

本赛题旨在引导高校学生深入理解 Agent 系统工程化的核心难题，不仅要求「能跑通 Demo」，更要求构建具备**编排定义、知识库集成、智能调度、执行监控、结果验证、反馈循环**六大能力的平台级作品，探索高效的工程编排与调度解决方案。

### 二、赛题目的

1. 培养多 Agent 系统工程的工程化能力：使学生掌握从 Agent 角色定义、工具注册、工作流编排到运行态调度的完整技术链，覆盖设计、开发、测试、部署全生命周期；
2. 深化 AI 基础理论与工具链思维：让学生理解 Harness 类平台的核心架构，掌握 MCP、Function Calling、RAG、记忆管理等关键技术的整合方法；
3. 建立可验证、可复现的 Agent 工程规范：要求平台具备执行日志、状态快照、结果校验与回滚能力，使 Agent 协作过程可追溯、可审计、可复现；
4. 推动「Agent + 行业」的深度耦合：鼓励学生将平台应用于真实或高保真的行业场景（如科研计算、软件开发、数据分析、智能制造、医疗辅助诊断等），沉淀一批可复用的 Agent 工作流模板与调度策略；
5. 构建完善的 Agent 自我验证与循环优化体系，提升系统在真实环境中的鲁棒性与可靠性；
6. 推动大模型 Agent 从理论走向工程化落地，为行业提供可复用的编排调度平台和解决方案。

### 三、赛题内容

#### 1. 题目概述

参赛队伍需自主选题，围绕「大模型 Agent 工具编排调度平台」进行系统设计与开发，选题场景不限，鼓励结合真实行业需求（如：AI4S 自动化科研数据分析、软件需求工程多 Agent 协作、智能巡检报告生成、多模态内容生产线等）。本赛题重点考察参赛队伍在 **Agent 编排调度层面的架构设计与工程实现能力**，而非单一基础大模型的生成能力。参赛队伍需构建一个能够自主完成复杂任务流的平台，实现从需求理解、工具调用、多 Agent 协作到结果验证的全链路闭环。

该平台应至少支持以下核心能力：

1. **Agent 团队定义与管理**：支持定义多个具有不同角色、技能、工具集与记忆能力的 Agent，支持 Agent 的动态注册、发现与版本管理；
2. **工作流编排**：提供可视化或代码化的工作流设计能力，支持顺序执行、并行分支、条件判断、循环迭代、子工作流嵌套等控制结构；
3. **智能调度引擎**：根据任务特征、Agent 负载、依赖关系与优先级，实现任务的动态分配与调度，支持至少一种自我循环（Self-Loop）或迭代优化机制；
4. **工具与外部系统集成**：支持通过 MCP、Function Calling、API 插件等方式集成外部工具（如代码解释器、数据库、搜索引擎、科学计算库等）；
5. **执行监控与结果验证**：提供运行时的状态监控、中间结果捕获、异常检测与自动/人工验证节点，支持对 Agent 输出进行交叉验证、基准比对或质量评估；
6. **反馈与自我优化**：支持基于验证结果的反馈循环，实现 Agent 提示词（Prompt）、工具选择或工作流路径的自适应调整。

#### 2. 技术要求

**• 平台功能完整性**

- 必须覆盖以下五个核心模块：**Agent 定义与配置、工作流编排、任务调度与执行、结果验证与监控、反馈循环与优化**；
- 必须提供可运行的系统原型，**不接受纯概念设计、纯 PPT 方案或无代码实现的论文综述**；
- 必须体现多 Agent 协作，**单 Agent 简单调用仅封装大模型 API 的作品不符合要求**；
- 必须包含至少一个自我循环或迭代优化机制（如：执行-验证-修正循环、Plan-Do-Check-Act 循环、ReAct 循环升级等）。

**• 人工智能与工具链使用**

- 必须基于大语言模型（LLM）作为 Agent 的推理核心，允许使用云端 API 或本地部署的开源模型；
- 必须体现 Agent 编排与调度的智能化，而非简单的硬编码流程；
- 鼓励使用 MCP（Model Context Protocol）、A2A（Agent-to-Agent）协议、Function Calling、RAG、向量数据库、记忆管理等一项或多项技术；
- 允许使用开源框架（如 LangChain、Dify 等）作为基础，**但必须在调度策略、验证机制或自我循环方面有明确定义改进或创新，禁止直接套用现成框架的默认示例**。

#### 3. 操作环境

- **大模型/领域科研模型**：不限，可使用云端大模型服务或本地自建服务器部署的开源模型；
- **开发框架与语言**：不限，Python、TypeScript、Go、Rust 等均可；前端技术栈不限；
- **部署环境**：不限，可使用个人服务器、云主机、容器化平台或 Serverless 架构；
- **数据与工具**：不限，鼓励接入真实 API 或开源工具集；如涉及敏感数据，需进行脱敏处理；
- **开源合规**：若基于开源项目二次开发，须严格遵守相应开源协议，并在文档中明确说明改动点与创新点。
